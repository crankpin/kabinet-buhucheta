## 0. Ответы на блокирующие вопросы (21.07.2026)

| # | Вопрос | Ответ |
|---|--------|-------|
| 1 | PHP на Timeweb | **Да.** Доступны PHP 8.0–8.5. Для v2 планируем **PHP 8.5**, код пишем переносимо (**совместимость ≥ PHP 8.4**) |
| 2 | Админка на этапе 1 | **Нет.** Только публичный сайт; админка позже |
| 3 | Ассеты в legacy | **На месте** в `legacy/public_html` (фото, мандарин, og, favicon, шрифты) |
| 4 | Резервная копия | **Сделана** |
| 5 | Где тестируем | Локально на ПК; боевой сайт не трогаем. Публикация — после проверки на **тестовом адресе** Timeweb |

### Зафиксированный стек v2

- Простые **PHP-шаблоны + `include`/`require`**
- **Без** Composer, фреймворков, БД, серверного Node.js
- Простой переносимый PHP (не опираться на уникальные фичи 8.5)
- Вся новая версия только в `/site`
- `/legacy` — только чтение
- Существующий публичный сайт **не менять** до явного переключения

### Локальный просмотр

Live Server PHP не выполняет. Для превью v2 использовать встроенный сервер PHP:

```bash
php -S localhost:8000 -t site
```

(или OpenServer/Laragon, если PHP не установлен в системе)

Одностраничный лендинг на чистом HTML/CSS/JS без CMS.

**Сильные элементы legacy:**

## 3. Предлагаемая техническая архитектура v2

### Принцип
**Самописный многостраничный сайт + общий layout на PHP includes**, без тяжёлого фреймворка и без CMS на первом этапе.

Почему так:
- Timeweb хорошо дружит с PHP;
- шапка/подвал/SEO-шаблон не дублируются на десятках страниц;
- контент страниц остаётся читаемым HTML (лучше для правок и SEO);
- позже можно добавить админку/JSON/бот, не меняя публичную IA;
- нет обязательного Node build на сервере.

### Альтернативы (отклонены)
| Вариант | Статус |
|---------|--------|
| Статический HTML с копипастой partials | отклонено |
| Astro / 11ty / Node build | отклонено |
| WordPress / Tilda | отклонено |
| Composer / фреймворки / БД | отклонено на этапе 1 |

### Стек v2 (зафиксировано)
- **PHP-шаблоны + `include`/`require`** — layout, header, footer, meta
- Целевая версия на Timeweb: **PHP 8.5**
- Код: простой, переносимый, совместимый как минимум с **PHP 8.4**
- Без Composer, фреймворков, БД, серверного Node.js
- Контент страниц — читаемый HTML внутри PHP-обёрток
- CSS/JS — исходники в `/site/assets/` (minify позже)
- Данные — `data/*.json` при необходимости
- ЧПУ — каталоги с `index.php` + `.htaccess` под Apache/Timeweb
- SEO — title/description/H1/JSON-LD/sitemap/robots на каждую страницу
- Аналитика — те же счётчики после тестовой проверки
- Админка / Telegram-бот — **после** публичного сайта
- Боевой сайт не трогаем до переключения с тестового адреса

### Как переиспользовать общее

```text
site/
├── includes/
│   ├── head.php          # meta, OG, JSON-LD hook, CSS/JS
│   ├── header.php        # лого, навигация, CTA
│   ├── footer.php        # контакты, регионы, соцсети, карта
│   ├── cta.php           # повторяемый блок консультации
│   └── breadcrumbs.php
├── data/
│   ├── reviews.json
│   └── meta/             # опционально: SEO-поля по slug
├── assets/
│   ├── css/
│   ├── js/
│   ├── images/           # из legacy + новые только по необходимости
│   └── fonts/
├── uslugi/...
├── nalogi/...
├── komu-pomogaem/...
├── regiony/...
├── poleznoe/...
├── o-karine/
├── kontakty/
├── politika-konfidentsialnosti/
├── 404.php
├── index.php             # главная + развилка «КТО ВЫ?»
└── .htaccess
```

Страница = тонкая обёртка:

```php
<?php
$page = [
  'title' => '...',      // только из утвержденного контента/docs
  'description' => '...',
  'canonical' => '...',
];
require __DIR__ . '/../../includes/head.php';
require __DIR__ . '/../../includes/header.php';
?>
<!-- уникальный контент страницы -->
<?php require __DIR__ . '/../../includes/footer.php'; ?>
```

Отрасли и регионы — один визуальный шаблон типа страницы + уникальный текст (без механической подстановки города).

## 5. Что перенести / адаптировать / не переносить

### Перенести без изменений (или почти)
- логотип, иконки SVG, orb-base/orb-gold, snowflake;
- фото Карины и мандаринка (после восстановления полных файлов);
- контакты/телефоны/email/Telegram/WhatsApp из legacy **если docs их не переопределяют**;
- `reviews.json` и логику вывода отзывов (адаптация разметки под новый layout);
- смысл чек-листа и квиза;
- Яндекс-верификации, ID Метрики/GA (если остаются те же);
- принцип отложенной загрузки аналитики.

### Адаптировать
- шапка и навигация → структура из `sitemap.md`;
- hero → резкий первый экран + развилка «КТО ВЫ?»;
- блок «услуги» → 3 коммерческие услуги, не 4 карточки legacy;
- блок «обо мне» → страница `/o-karine/` + короткий блок на главной;
- SEO-текст-простыня с главной → разнести по посадочным (не дублировать простыню на `/`);
- footer → регионы, услуги, полезное, нормальная политика;
- privacy → реальная политика под формы/метрику;
- визуальный ритм → принципы из `visual-principles.md` (не редизайн «с нуля», а усиление структуры);
- районы Ростова как отдельные SEO-сущности → **не делать** (docs запрещают); Ростов остаётся одной региональной страницей.

### Не переносить
- одностраничную модель как основу сайта;
- SEO-простыню на главной в текущем объёме;
- позиционирование «только ИП Ростов / налоговый шок» как единственный оффер;
- `privacy.html` с текстом про API/аудит кода;
- декоративный снег как обязательный элемент (опционально, с `prefers-reduced-motion`);
- выдуманные кейсы/цены/гарантии сверх docs;
- отдельные посадочные «восстановление учёта» / «ответы ФНС» как услуги;
- WordPress/Tilda.

## 6. Повторное использование компонентов

| Компонент | Организация |
|-----------|-------------|
| Шапка | `includes/header.php` + конфиг меню из одного массива |
| Подвал | `includes/footer.php` (услуги, регионы, контакты, соцсети) |
| Навигация | единый source of truth; мобильное меню из тех же пунктов |
| SEO | `head.php` принимает `$page['title'|'description'|'canonical'|'og'|'schema']` |
| CTA | общий partial; тексты кнопок без обещаний вне matrix |
| Услуги / отрасли / регионы | page-type templates + уникальный контентный файл на URL |
| Интерактивы | JS-модули в `assets/js/`; разметка на `/`, `/poleznoe/...` |
| Отзывы | общий loader + JSON |

Контент страниц **не придумывается**: на этапе вёрстки — каркасы блоков по `page-types.md`; тексты — только из docs или отдельно утверждённых материалов.

## 8. Риски и правила безопасности

- `/legacy` — только чтение; все изменения только в `/site`.
- Не заливать черновик на боевой домен до приёмки.
- Не выдумывать услуги, отрасли, квалификацию, кейсы, цены, географию, гарантии, факты о Карине.
- При конфликте legacy ↔ docs побеждают **docs**.
- Интерактивы и узнаваемые ассеты сохраняем; «конструктивизм» — в сетке/ритме, не в агитстиле.
