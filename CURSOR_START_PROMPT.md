# Первый промпт для Cursor

Скопируй текст ниже в Agent/Work-режим Cursor после подготовки папки проекта.

---

Ты работаешь над новой многостраничной версией сайта «Кабинет Бухучёта».

Перед началом внимательно изучи:

- все документы в `/docs`;
- существующий сайт в `/legacy/public_html`.

Папка `/legacy` предназначена только для чтения.

Никогда не изменяй, не удаляй и не перемещай находящиеся там файлы.

Новую версию создавай только внутри `/site`.

Основные задачи новой версии:

- отдельная посадочная страница для бухгалтерского сопровождения ИП;
- отдельная посадочная страница для бухгалтерского сопровождения ООО на УСН;
- отдельная услуга налогового консультирования;
- многостраничная информационная архитектура;
- региональные страницы для Москвы, Московской области, Ростова-на-Дону, Ростовской области, ЛНР и ДНР;
- сохранение сильных элементов нынешнего сайта;
- хорошая индексация, скорость, доступность и мобильная адаптация.

На главной предусмотри интерактивную развилку:

КТО ВЫ?

[ Я — ИП ]  
[ У меня ООО ]  
[ У меня несколько разных организаций ]

Первая кнопка ведёт к сопровождению ИП.

Вторая — к сопровождению ООО на УСН.

Третья открывает короткий сценарий для владельца нескольких организаций или сочетания ИП и ООО.

Визуальные принципы Маяковского и Родченко учитывать при построении структуры, сетки и ритма, но не делать буквальную советскую стилизацию и не превращать сайт в агитационный плакат.

На первом этапе:

1. Проанализируй документы и старый сайт.
2. Определи используемые технологии текущего сайта.
3. Предложи техническую архитектуру версии v2 без неоправданного усложнения.
4. Создай файл `/docs/implementation-plan.md`.
5. Покажи предполагаемое дерево файлов и страниц.
6. Перечисли элементы старого сайта, которые следует:
   - перенести без изменений;
   - адаптировать;
   - не переносить.
7. Опиши, как будет организовано повторное использование шапки, подвала, навигации, SEO-метаданных, страниц услуг, отраслей и регионов.
8. Предложи порядок реализации небольшими этапами.
9. Не создавай страницы и не изменяй код до утверждения плана.

Не придумывай:

- услуги;
- отрасли;
- квалификацию;
- кейсы;
- цены;
- географию;
- гарантии;
- факты о Карине.

Если документы противоречат старому сайту, приоритет имеют документы в `/docs`.

В конце задай только блокирующие вопросы, без ответа на которые нельзя выбрать техническую архитектуру.
